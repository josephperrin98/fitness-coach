# v0 design: daily check-in, adherence score, dashboard

Agreed 19 Oct 2026. Supersedes the order in `docs/build-plan.md` where they differ.

## Goal

One working loop, end to end: a daily check-in in Claude decides today's session,
code scores how closely the plan was followed, and a dashboard shows plan, actuals
and recovery together. Built so it is useful to its owner and legible to a stranger.

## Decisions

| # | Decision |
|---|---|
| D17 | Adherence per session: `r = actual / planned`. Short: `100 * r`. Over: `100 - 50 * (r - 1)`, floor 0. Missed: 0. Moved to another day in the same week: -10. Falling short costs twice what overshooting does. Thresholds live in `rules.yaml` (`personal_choice`). |
| D18 | Daily check-in decides today only. The plan is reviewed weekly, or mid-week only when the user asks. |
| D19 | Sessions are planned individually: date, kind, target, unit (minutes, or km for the long run), optional zone ceiling. Weekly totals stay and must agree with the sessions. |
| D20 | Autonomy scales with risk. The agent may record a same-day change that makes the session *easier* (shorter, or rest) after asking the user in chat. Anything that adds load, or changes future weeks, goes through propose/confirm, and confirm is human-only (CLI). Enforced in code. |
| D21 | Strava data reaches an LLM only through Strava's connector, and is never stored. The check-in record holds decisions and the user's own inputs only. |
| D22 | The dashboard is one HTML file. In the Claude app it reads Strava, Whoop and coach-core live; anywhere else (GitHub Pages) it loads synthetic `demo-data.json` produced by the same Python code. |
| D23 | Scoring and view logic live in Python (`coach/`), exposed as MCP tools. The page fetches and renders; it computes nothing that matters. |

## Pieces

```
 Strava connector ─┐
 whoop-mcp (JSON) ─┼─> dashboard/index.html ──> coach-core MCP (score_week, activity_cost, calendar)
                   │                                   │
 daily-check-in skill ─> coach-core MCP (get_today, check_gate, record_check_in)
                                                       │
                                     coach/ (plan, rules, validator, score, checkins) + SQLite
```

1. `coach/plan.py`: `Session` inside `Week`.
2. `coach/score.py`: session and week adherence, execution (share of minutes at or below the zone ceiling), activity cost.
3. `coach/checkins.py`: one record per day; refuses an adjusted target above plan.
4. `coach/mcp_server.py`: stdio server. No confirm tool.
5. `whoop-mcp`: date-range tools returning JSON (existing tools unchanged).
6. `skills/daily-check-in/SKILL.md`.
7. `dashboard/`: calendar, adherence score, what each activity costs you. Demo mode.
8. `evals/`: scenarios graded on stored state (what was recorded), not on wording.

## Out of v0

Weekly review skill, plan generator, intake for other runners, plugin packaging,
bedtime / time-of-day / efficiency views (need weeks of data first).

## Testing

pytest for every function in `coach/`. Evals run the real skill against a scenario
database and check the record it leaves.
